# 設計書テンプレート（Markdown で書いて、PDF にする）

**Markdown を書くだけで、客先提出品質の PDF 設計書ができます。**
外枠・資料番号欄・社名といった会社様式、目次、章番号、図表番号、相互参照、改ページは
すべて自動です。執筆者は本文の中身だけに集中してください。

社内レビュー用の HTML（章ごとのページ・全文検索つき）も、同じ原稿から作れます。

> **書き方（記法）を知りたい方は [AUTHORING.md（執筆ガイド）](AUTHORING.md) へ。**
> 表・図・IPO図・相互参照の書き方はすべてそちらにあります。まず読むのはこちらです。

## できること

- **目次を自動生成** — 章番号・リーダー線・ページ番号つき。本文を直せば自動で追従します
- **章番号を自動採番** — 4階層（1.1.1.1）まで
- **図表番号を自動採番** — 「図 3.2-1」「表 3.1-1」の形式（連番は節ごとにリセット）
- **図表の相互参照** — 本文に `@fig-xxx` と書けば「図 3.2-1」に置き換わります。図を増減して
  番号がずれても、本文側は書き直し不要です
- **表のセル結合** — 大分類・中分類の縦結合を自動化（HTML タグを書く必要はありません）
- **大きな表のページ分割** — 同じ表番号で「（1／3）」と続きます
- **横向きページ・IPO図** — 縦横の混在も定型ページも用意ずみ
- **フローチャート**（mermaid）— 文字で書いた図が、そのまま図版になります
  （PDF に載せるときだけ、最初に少し準備が要ります → [ADVANCED.md](ADVANCED.md#4-mermaid-を使う場合)）
- **章ごとのファイル分割** — 何ファイルに分けても、番号は文書全体で通し番号になります

## 1. 最初に一度だけの準備

### 1-1. Quarto をインストールする

[Quarto の公式サイト](https://quarto.org/docs/get-started/)からインストーラを
ダウンロードして実行します。PDF を作る仕組み（Typst）はこの中に入っているので、
**ほかに入れるものはありません**。

インストール後は VSCode を再起動してください。

### 1-2. VSCode に拡張機能「Quarto」を入れる（おすすめ）

VSCode の拡張機能ビュー（左のアイコン、または `Ctrl+Shift+X`）で **Quarto** を検索して
インストールします。書きながらプレビューを見られるようになります
（コマンドパレット `Ctrl+Shift+P` → `Quarto: Preview`）。

### 1-3. 初期化コマンドを1回だけ実行する

このフォルダを VSCode で開き、メニューの **「ターミナル」→「新しいターミナル」** で
ターミナルを開いて、次を実行します。

```bat
.\template\setup.bat docs
```

`OK: initialized "docs".` と出れば成功です。**この操作は最初の一度だけ**で、
以降のビルドでは自動で実行されます。

> macOS / Linux をお使いの場合は、`.bat` の代わりに `.sh` を使ってください
> （`./template/setup.sh docs`）。以降のコマンドも同じ読み替えです。

### 1-4. 表を書くならフォントを変える（重要）

VSCode の初期フォント（Consolas）には**日本語の文字が入っていません**。日本語は別の
フォントで代用表示されるため文字幅がそろわず、**表の罫線が画面上でガタガタになります**。
表だけ極端に書きづらいのはこれが原因です。

日本語もきれいにそろうフォント（`BIZ UDゴシック` など。日本語版の Windows 10/11 なら
最初から入っています）を指定してください。このフォルダの中の `.vscode/settings.json`
に書けば、**この設計書を開いたときだけ**切り替わります。ファイルが無ければ、コマンド
パレット（`Ctrl+Shift+P`）で `Preferences: Open Workspace Settings (JSON)`
（日本語表示なら「基本設定: ワークスペース設定を開く (JSON)」）を実行すると作られます。

```json
{
  "editor.fontFamily": "'BIZ UDゴシック', Consolas, monospace"
}
```

これは**画面の見た目だけ**の設定です。PDF や HTML の文字は別に決まっているので、
出来上がりには影響しません。画面上で罫線がそろっていなくても、列幅は中身の量から
自動計算されるので出力は崩れません。

## 2. 原稿を書く

原稿は **`docs/` フォルダの中**にあります。触るのは基本的に次の2か所だけです。

| 何をしたいか | どこを編集するか |
|---|---|
| 本文を書く・直す | `docs/chapters/` の中の `.qmd` ファイル |
| 章を増やす・減らす・並べ替える | `docs/_quarto.yml` の `chapters:` の一覧 |
| 文書番号・表題・会社名を変える | `docs/_quarto.yml` の上のほう（`doc-number` など） |

`.qmd` ファイルは**中身がほぼ Markdown**です。書き方（表・図・相互参照・IPO図など）は
**[AUTHORING.md（執筆ガイド）](AUTHORING.md)** にまとめてあります。

`docs/` は付属のサンプル（受注管理システムの基本設計書）です。中身を書き換えて
使ってください。フォルダ名も変更できます（→ [ADVANCED.md](ADVANCED.md#2-執筆フォルダdocsを改名したいとき)）。

## 3. PDF と HTML を作る

ターミナルで次を実行します。

```bat
:: PDF（納品物）→ docs\design-doc.pdf
.\template\build-qmd.bat docs

:: HTML（社内レビュー用・章ごとのページ）→ docs\_book\index.html
.\template\build-html.bat docs
```

- 初回は少し時間がかかります。`OK -> ...` と出れば成功です。
- **両方を残したいときは、PDF → HTML の順**で実行してください。PDF と HTML は同じ作業
  フォルダを使うので、**あとから実行したほうが前の出力を消します**（PDF 本体は
  `docs\design-doc.pdf` に取り出されるので残りますが、HTML は消えます）。
- HTML はフォルダ一式（`docs\_book`）で完結しています。共有するときは `_book` を
  zip して渡せば、相手はそのまま `index.html` を開いて読めます。

## 4. うまくいかないとき

| 症状 | 対処 |
|---|---|
| コマンドが「見つかりません」と言われる | VSCode で**このフォルダを開いた状態**のターミナルか確認してください（`.\template\...` はフォルダの直下から実行します） |
| `quarto` が見つからない | Quarto のインストール（1-1）後、VSCode を再起動してください。確認は `quarto --version` |
| 表の罫線が画面でそろわない | フォント設定（1-4）を行ってください。出力される PDF・HTML は崩れていません |
| 図（mermaid）が PDF に出ない | PDF に図を載せるには追加の準備が必要です（→ [ADVANCED.md「mermaid を使う場合」](ADVANCED.md#4-mermaid-を使う場合)）。文字だけの原稿なら不要です |
| 表番号・図番号が思った番号にならない | 番号は文書全体の通し番号です。書き方は [AUTHORING.md](AUTHORING.md) を参照してください |
| PDF を作り直したら HTML が消えた | 仕様です。PDF → HTML の順に作り直してください（→ 3章） |
